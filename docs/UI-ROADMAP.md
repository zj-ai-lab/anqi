# 案齐 UI 统一路线

本文档记录 UI 一致性工作的当前基线、后续顺序和验收门槛。它是 agent 开始 UI 修改前的入口，和 [UI-AGENT-WORKFLOW.md](UI-AGENT-WORKFLOW.md)、[UI-COMPONENTS.md](UI-COMPONENTS.md) 配合使用。

## 已完成：第一阶段

- 案件详情和费用页的联系人摘要、案款账本、状态标签和操作按钮完成统一。
- 联系人事实条使用固定字段列，按钮文字居中，桌面控件 32px、移动端控件 44px。
- 案款状态列、外部来源标签、长文本截断和窄屏双行布局完成收口。
- `pro`、`paper`、`jade` 三套皮肤已通过桌面端和 390px 移动端资金 UI QA。
- 组件契约、agent 工作流、设计令牌和变更记录已落盘。

## 第二阶段：共享层

已完成本批次：

1. **Modal 共享层**：统一弹窗的背景 inert、Esc 关闭、Tab 循环、首焦点、恢复焦点和无障碍命名；today/case/calendar 相关弹层沿用 `public/js/modal.js`。
2. **控件尺寸令牌**：建立桌面 `--control-h: 32px`、移动 `--control-touch-h: 44px`，接入 `.btn`、`.btn.small`、事实条动作和三页既有控件。

后续项目：

1. **案款账本行契约**：将剩余内联 `grid-column` 改为 `data-slot` 或稳定的语义类名，统一窄屏行为。
2. **状态标签基类**：统一 `.chip`、`.pill`、`.ledger-chip` 及其他状态标签的骨架和高度。

## 第三阶段：高频页面迁移

1. 今日页：长中文待办、日期和操作列不互相挤压。
2. 案件列表：复选框保留 16px 视觉框，但命中区达到 44×44px。
3. 日历页：图例、快捷菜单、“更多”和托盘摘要统一触控区，月格不横向溢出。
4. 通讯录：迁移为姓名/合作摘要/动作三列结构。
5. 统计、用户中心和分享修复页：处理长金额、空态、错误态和窄屏布局。

## 第四阶段：全站 QA 门禁

页面矩阵：`index`、`cases`、`case`、`fees`、`contacts`、`calendar`、`stats`、`profile`、`share-repairs`。

每个页面检查三套皮肤和 1440、1366、1024、1000、768、390 视口，并覆盖正常、空值、长中文、长按钮、0 值、错误、禁用和加载状态。验收包括无横向溢出、按钮文字居中、移动端控件至少 44px，以及表单名称、焦点、弹窗语义和关闭后焦点恢复。

## 每个 UI 任务的完成条件

- 先查组件目录和本路线，再决定修改令牌、共享组件还是页面结构。
- 更新组件契约或设计令牌，并留下页面 QA 证据。
- 保留 JavaScript 选择器、事件钩子和数据属性。
- 通过对应页面 QA；完整仓库检查若被既有迁移测试阻断，记录具体失败位置和原因。
