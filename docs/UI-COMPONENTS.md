# 案齐 UI 组件目录

> 这是 agent 查找和复用 UI 的入口。视觉规范仍以 [`DESIGN-TOKENS.md`](DESIGN-TOKENS.md) 为准，运行代码仍以 [`public/css/style.css`](../public/css/style.css) 为准。
>
> 组件目录记录“怎么用”和“怎么验收”，不复制整份 CSS。组件需要改变尺寸、间距、颜色或皮肤映射时，先更新设计令牌文档，再更新实现和本目录。

## 使用规则

- 先查本目录，再决定是否需要新增类名。
- 组件的共享布局放在 `style.css` 层 A；皮肤只在层 B 提供材质变量和允许的表面属性。
- HTML 改动必须保留页面 JavaScript 使用的 id、class、`data-*` 属性和事件钩子。
- 一个组件的状态、空值、长文本和移动端行为没有写清楚，就不能直接复制到新页面。
- 组件改动必须在 `pro`、`paper`、`jade` 和 390px 下验证。

## 第一批组件

| 组件 | 现有类名/入口 | 用途 | 当前动作 |
|---|---|---|---|
| 按钮 | `.btn`、`.btn.small`、`.btn.primary`、`.btn.ok`、`.btn.danger` | 页面和面板动作 | 固定文字居中、禁用、焦点和移动端高度 |
| 状态标签 | `.chip`、`.pill`、`.dot`、`.ledger-chip` | 期限、款项和流程状态 | 普通标签复用语义色；账本状态标签使用 inline-flex、20px 最小高度，日期与来源前缀不能压到下一列 |
| 面板 | `.panel`、`.panel-body`、`.p-head`、`.p-title`、`.p-foot` | 工作区的主要容器 | 统一标题、内容区、脚部和分隔关系 |
| 卡片 | `.card`、`.case-card`、`.tile` | 案件、统计和旧页面容器 | 收敛旧卡片与新面板的使用边界 |
| 通用列表行 | `.row`、`.inb-row`、`.todo-row`、`.hear`、`.pay-row`、`.gap-row` | 今日、案件和收件箱列表 | 固定列、长文本、操作区和空态 |
| 事实条 | `.factstrip`、`.factstrip-more` | 当事人、参与人、分成约定等固定事实 | 固定“字段名/内容/动作”三列和换行规则 |
| 账本 | `.ledger`、`.ledger-row`、`.ledger-detail` | 费用、款项和重复账目 | 固定列、状态栏杆、展开关系和数字对齐 |
| 归档门 | `.archive-door` | 已完成、已忽略和历史区 | 统一折叠、摘要和异常内容可见性 |
| 费用款项 | `.fee-item-block`、`.fee-item`、`.fee-share-result` | 单笔律师费及分成结果 | 统一事实、条件、结算和动作的阅读顺序 |
| 参与人摘要 | `.factstrip--contacts`、案件联系人/参与人摘要骨架 | 展示当事人、合作对象和操作 | 首列 64px、字段名不换行、动作列按内容取宽；按钮桌面 32px、窄屏 44px |
| 期限跑道 | `.runway`、`.rw-lead`、`.rw-row`、`.rw-trk` | 最近期限和倒计时 | 保持五列骨架、状态可见和窄屏可读 |
| 时间线 | `.timeline`、`.tl-item`、`.tl-actions` | 事件、日志和变更记录 | 固定日期、正文和动作列 |

## 优先级

- **P0**：信息被遮挡、状态误读、主要动作无法完成。
- **P1**：高频页面中的错位、溢出、按钮不可用或重复样式。
- **P2**：低频页面的间距、字重、材质和细节问题。

先处理 P0 和 P1。P2 在对应页面迁移时一起收口，避免为了单个像素问题重复改动共享骨架。

## 完成标准

组件完成需要同时满足：

1. DOM 契约和现有 JS 钩子仍然成立。
2. 共享布局没有把几何规则写进单独皮肤。
3. `pro`、`paper`、`jade` 的页面结构和关键尺寸一致。
4. 390px 下没有横向滚动；可操作控件高度至少 44px。
5. 正常、空值、长中文、长按钮文案、禁用和错误状态都可读。
6. `npm run check` 和对应的页面 QA 通过。
